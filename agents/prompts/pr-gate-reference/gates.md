# Gate routing — which commands a change must pass

Source of truth is the `Makefile` and `.github/workflows/ci.yml`. If they
disagree with this table, they win — and fix this table.

**Who runs these.** On a PR, `ci.yml` runs two jobs:

- **`checks`:** `make check`, `make fmt` (must leave no diff), `make check-js`, `make test-web`, `make test-dom`, `make check-md` and `make check-actions`.
- **`test` (Linux):** `make build`, `make test-odin-green` (and `SERIAL=1`), `make test-eventloop-odin`, `make test-runtime-odin`, `make test-html-odin`, `make test-http-odin`, `make test-sqlite-odin` and `make test-bench-pages-smoke`.

The `mutation` job is manual-only (`workflow_dispatch`). `/pr-gate` is invoked by a human, locally. `--review-only` executes no `make` target and reads CI's conclusions instead; it is for reviewing from a machine without the toolchain.

Routed targets that are **not** in CI need a local run:

- `make test-fetch-html-smoke`;
- `make test-stdio`;
- `make test-mutation`.

Since S5 (#130) Larva has one surface, the Window profile, and its only oracle is Chrome. The node-vs-Lava suites (`test-lava`, `test-compat*`, `test-property`, `test-eventloop-lava`, `test-fetch-smoke`, `bun-buffer-tests`, `api-surface`) were deleted with it. `runtime/gates/route-gates.mjs` may still name some of them: a human updates it, since it is protected.

**What CI itself runs on a pull request** is decided by `scripts/ci-scope.mjs`, not by this table:

- a docs-only PR runs only the lints;
- a tooling-only PR (gates, agents, Node scripts) adds `check-js` and `make test-mutation CHANGED=1`;
- any other PR runs everything.

`make check-actions` runs whenever any `.github/workflows/*.yml` changed. actionlint catches what a YAML parse cannot: a context used where it is not available, a bad `needs`, shellcheck errors inside `run:`.

## Perf claims

Any PR titled `perf(...)`, or claiming speed or memory anywhere in its body, must carry numbers with their method: `make bench-pages` (pages per thread), a micro-benchmark run interleaved against master, or a profile. For JSC's sampling profiler, set `JSC_useSamplingProfiler=1` plus a dump directory.

`make bench` runs `bench/micro` under `lava run` (Window globals) on a baseline binary and on `bin/lava`, interleaved, and prints ns/op for both with the new/base ratio: that is the "micro-benchmark run interleaved against master" (the baseline defaults to `origin/master`, built once in a temporary worktree; `BASE=<path>` or `BASE_REF=<ref>` picks another). `make bench-gate` fails on a new/base ratio above its cap in `bench/thresholds.json`, caps set from measured A/A noise (`bench/README.md`). Both are local only, not in CI. There is no Chrome column yet; Node is no longer a yardstick for them.

## Backends

Native-function creation has two backends. Normally every native is a JSC host function created through a dlsym'd private symbol. With `LAVA_HOSTFN_DISABLE=1` they all come from `JSObjectMakeFunctionWithCallback` instead. The two are **not** observably identical: `.length` and constructibility differ (see `inject_native_function`). The suite that ran everything under the fallback went with the Node surface, so a change to native registration needs a by-hand `LAVA_HOSTFN_DISABLE=1 make test-web`.

## Known-gap files

`tests/web/known-gaps.txt` belongs to the Window suite, and `tests/dom/known-gaps.txt` (per view) to the DOM suite.

- **Each entry** names the stage that closes it (or `unplanned`) and a reason.
- **Each gap is pinned** to a Lava output in `known/<case>.lava`, refreshed only by `--update-known <case>`. A diff to a pin is a behaviour change to review.
- **Adding** a case to a gap file is a regression and needs an explicit reason.
