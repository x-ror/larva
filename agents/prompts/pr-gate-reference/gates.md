# Gate routing — which commands a change must pass

Source of truth is the `Makefile` and `.github/workflows/ci.yml`. If they
disagree with this table, they win — and fix this table.

**Who runs these.** On a PR, `ci.yml`'s Linux job executes the subset listed under
"CI during the Node-profile removal" below. Nothing else runs them: `/pr-gate` is
invoked by a human, locally, and `--review-only` (which executes no `make`
target and reads CI's conclusions instead) is for reviewing from a machine
without the toolchain. **Three** routed targets are **not** in CI — `make bun-buffer-tests`,
`make api-surface` and `make test-compat-lava-strict` — so a diff that routes to one of
those needs a local run, or a new CI step if it should be enforced.

**CI during the Node-profile removal.** Since S3 the `test` job runs on every push and
PR again, but only what is meaningful and green on the default build: `make build`,
`make test-odin-green` (and `SERIAL=1`), `make test-eventloop-odin`,
`make test-runtime-odin`, `make test-html-odin`, `make test-http-odin`,
`make test-sqlite-odin`, `make test-fetch-smoke` and `make test-bench-pages-smoke`.
`test-odin-green` is `cmd/lava` minus `cmd/lava/known-node-red.txt` — the tests whose
pages still require a deleted Node module, each listed with what it needs, until S5a
rewrites them. NOT in CI until their suites are re-based on the Window profile:
`make test-lava`, `make test-lava-nohostfn`, `make test-property`, `make test-stdio`
and `make bench-gate` (a routed one of these still needs a local run, read against
master's red set, not as a pass/fail). The `mutation` job stays manual-only until S5b.
(`make test-scripts` runs in CI inside `make check-js`; `make test-web` runs in the
`checks` job, after a build of its own there.)

**What CI itself runs on a pull request** is decided by `scripts/ci-scope.mjs`, not
by this table: a docs-only PR runs only the lints, a tooling-only PR (gates, agents,
Node scripts) adds `check-js` and `make test-mutation CHANGED=1`, and any other PR
runs every gate with the mutation gate as `CHANGED=1`. Every push to `master` runs
everything, including the whole mutation manifest. This table is still what a
change MUST pass; a gate CI skipped on the PR is checked on `master`.

**Machine-readable routing:** `node runtime/gates/route-gates.mjs <paths>`
(or `--from-git`). Prefer that over hand-parsing this table; if Makefile/ci.yml
disagree with this file, they win — fix this file.

## Always

| Command                         | Covers                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `make check`                    | Odin type-check of `cmd/lava`, `pkg/runtime`, `eventloop`, `picohttpparser`, `pkg/std/sqlite`, `pkg/http`, `pkg/jsc` — **plus** cross-target front-end checks of `pkg/runtime` and `pkg/http` for `windows_amd64` and `darwin_arm64`. A change that breaks a platform stub fails here.                                                                                      |
| `make build`                    | Links `bin/lava`. Required before every `*-lava`, smoke, or bench target.                                                                                                                                                                                                                                                                                                   |
| `make test-odin-green`          | `cmd/lava` tests minus `cmd/lava/known-node-red.txt` (`scripts/run-odin-green.sh`) — what CI runs. Fails on a new red, on a listed name that no longer exists, on a listed test that now PASSES (the list only shrinks), and on a `@(test)` the discovery cannot pair with a name. The list and the script are pinned by sha256 in `ci.yml`: widening either needs a human. |
| `make test-odin-green SERIAL=1` | The same on ONE runner thread — the only configuration where several `lava.eval` sites share a thread, and therefore the thread-local host-native registry and JSC's recycled context addresses. Replaces `make test-odin-serial`, which is red by design (it runs the listed tests too).                                                                                   |
| `make test-web`                 | The Window-profile oracle (Chrome recordings).                                                                                                                                                                                                                                                                                                                              |

`make fmt` (`odin strip-semicolon`) before committing Odin.
`make check-js` whenever any `.js`/`.mjs`/`.cjs` under `pkg/runtime/js`, `tests`,
`scripts`, or `bench` changed — it runs format, lint, the JS module-graph check (`check-js-graph`), and the
primordials ratchet.
`make check-md` whenever any `.md` changed — `bun fmt --check` plus markdownlint over the
repo's own docs (lint config and the rationale for its two disabled rules: `.markdownlint-cli2.jsonc`).
`make check-actions` whenever any `.github/workflows/*.yml` changed — actionlint
catches what a YAML parse cannot: a context used where it is not available, a bad
`needs`, shellcheck errors inside `run:`.

## Perf claims

Any PR titled `perf(...)`, or claiming speed/memory anywhere in its body, must
carry numbers: `make bench` (ratio table), `make bench-pages` (pages per thread), or a
profile. JSC sampling profiler:
`JSC_useSamplingProfiler=1` plus a dump directory.

`make bench-gate` enforces `bench/thresholds.json`; it is out of CI during the
Node-profile removal (above), so run it locally when touching a floor.

## Backends

Native-function creation has two backends for the same reason. Normally every
native is a JSC host function created through a dlsym'd private symbol; with
`LAVA_HOSTFN_DISABLE=1` (`make test-lava-nohostfn`) they all come from
`JSObjectMakeFunctionWithCallback` instead. The two are **not** observably
identical — `.length` and constructibility differ, see `inject_native_function` —
so a change to native registration is not verified from one of them either.

## Known-gap files

`tests/web/known-gaps.txt` is the Window suite's: each entry names the removal stage
that closes it (or `unplanned`) and a reason, and is held to a pinned Lava output in
`tests/web/known/<case>.lava` — refreshed only by `node scripts/run-web-oracle.mjs
--update-known <case>`, and a diff to it is a behavior change to review.

`known-lava-gaps.txt` (per suite) lists cases skipped under Lava.
`make test-compat-lava` skips them; `make test-compat-lava-strict` does not.
A diff that _adds_ a path to a gap file is a regression needing an explicit reason.
