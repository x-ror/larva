# Cases where `lava run --surface=web` does not print what Chrome recorded.
#
#   <case> <stage>: <reason>
#
# The stage is the step of the Node-profile removal that closes the gap
# (tests/web/README.md lists them). Each listed case is held to its pinned Lava output
# in tests/web/known/<case>.lava, so a gap that changes is a failure too; one that
# starts matching Chrome fails until its line and pin are removed.
# `unplanned` marks a gap no removal stage closes: it needs an issue of its own.

abort-signal unplanned: EventTarget is not a global on either surface, so `signal instanceof EventTarget` throws ReferenceError; the AbortSignal behavior before it matches Chrome
fetch-body-utf8 S4d: a string body sets no content-type (Chrome: text/plain;charset=UTF-8)
fetch-classes S4d: headers iterate in insertion order instead of sorted, Request mode/credentials/cache are empty, Response.error().type is "default", and a string body sets no content-type, so blob().type is "" (as fetch-body-utf8)
fetch-errors S4d: undici-style messages where Chrome has WebIDL text, and five checks are missing (Headers pair length, Request method token and forbidden methods, Response status range, null-body status with a body)
fetch-network S4d: fetch(request) sends no content-type for a string body the Request carries; the other network lines match Chrome
perf-now unplanned: performance is a plain object (no Performance brand, no toJSON)
robust-console-poisoned unplanned: bootstrap/console.js reads Array.prototype.slice live, so a page that replaces it can no longer log (print writes through console.log on Lava)
robust-resizable-views unplanned: Chrome refuses a view over a resizable ArrayBuffer in every WebIDL byte argument (no [AllowResizable]); Lava reads the view's current bytes. Closes with WebIDL conversions (#12)
robust-view-probe unplanned: as robust-resizable-views: Chrome refuses the resizable-backed window, Lava decodes it as empty (it never reads the stale bytes this case guards against)
shape-abort unplanned: EventTarget is not a global (#114): AbortSignal's [[Prototype]] is Function.prototype and its prototype's Object.prototype, and AbortSignal.prototype carries addEventListener/removeEventListener/dispatchEvent itself; everything else matches Chrome
shape-console unplanned: console has no context/createTask/memory (#114); every other member matches Chrome's shape
shape-crypto unplanned: no crypto.subtle (SubtleCrypto is not implemented); the Crypto interface and getRandomValues/randomUUID match Chrome (#114)
shape-fetch S4d: Request's and Response's attributes are instance properties, Body is their parent class, Request.prototype has no clone/formData/textStream, and Response no formData/textStream/redirect; every member Lava has is native-shaped (#114)
shape-missing unplanned: the Chrome globals of the shape-* families Larva does not implement (TextEncoderStream, FormData, EventTarget, SubtleCrypto, Performance, reportError, …) — one line each, so implementing one is a visible change
shape-performance unplanned: performance is a plain data property holding a plain object — no Performance interface, getter, toJSON, mark/measure or entries (as perf-now); now() alone is native-shaped (#114)
streams-byte unplanned: no readable byte streams (ReadableByteStreamController, type 'bytes', BYOB reads)
timers-string-handler unplanned: a non-function handler is ignored (no timer, the delay not converted) where Chrome converts it to a string and runs it as a script when the timer fires; needs a native that evaluates source in the page's global scope
url-errors S4e: node's ERR_INVALID_URL and URLSearchParams messages where Chrome has WebIDL text and no code (createObjectURL already matches, S4c)
url-host-space unplanned: Chrome percent-encodes a space in a special URL's host and accepts it; Lava follows the WHATWG parser and throws. Deciding whether to follow Chrome here is parser work, not message work
wasm-streaming unplanned: no WebAssembly.compileStreaming/instantiateStreaming (Blink's, over a Response; JSC GTK has none) — a fingerprint; not stubbed, since a stub that rejects breaks loaders that would take their ArrayBuffer path; the implementation over Response needs an issue of its own
